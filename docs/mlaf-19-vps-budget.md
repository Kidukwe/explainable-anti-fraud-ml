## Что разместим на VPS

На одной ВМ размещаем демо целиком — интерфейс, FastAPI и инференс одной обученной табличной модели после интеграции. По черновику контракта API оценивает одну операцию по клику. Дневной пакетный расчёт, обучение модели и генерацию текстов LLM для демо планируем выполнять отдельно. На сервере храним нужные для демо признаки, версию модели и заранее подготовленные объяснения. [Требования из PR №4](https://github.com/Kidukwe/explainable-anti-fraud-ml/pull/4), [контракт инференса в PR №5](https://github.com/Kidukwe/explainable-anti-fraud-ml/pull/5), [интерфейс в PR №7](https://github.com/Kidukwe/explainable-anti-fraud-ml/pull/7)

PR №4 оценивает профиль с табличной моделью в **2 vCPU, 4 ГиБ RAM и 30–40 ГиБ SSD**. Оба тарифа Play2Go закладывают **4 vCPU и 8 ГБ RAM** как запас под подготовку признаков, модель и одновременные обращения. У DE-3 больше места для образов и артефактов. Выигрыш по задержке от Ryzen на этом проекте предстоит измерить. В `main` работает базовый API, а `/readyz` сообщает об отсутствии модели. Решение между CatBoost и LightGBM остаётся открытым. После интеграции проверим p95 запроса оценки, загрузку CPU и пиковую RAM при одном и пяти одновременных запросах. Живую LLM на той же ВМ оцениваем отдельно при изменении сценария демо. [Оценка ресурсов](vps-llm-requirements.md#прикидка-мощностей), [текущий API](../backend/app.py), [обзор в PR №8](https://github.com/Kidukwe/explainable-anti-fraud-ml/pull/8)

## Docker Compose, панель и CD

- **Docker Compose.** В выбранной локации нужны Linux x86-64, предпочтительно Ubuntu 24.04 LTS, доступ по SSH и входящий HTTPS на публичном IPv4. Текущий Compose поднимает один сервис с локальным портом 8000 и проверкой `/healthz`. Для демо понадобятся обратный прокси с HTTPS и ограничением доступа. Чтобы запустить модель, образ должен содержать зависимости инференса, а приложению потребуется совместимый артефакт модели. Сборку интерфейса из PR №7 можно выполнять в CI и отдавать на VPS как статику. [Compose](../docker-compose.yml), [Dockerfile](../Dockerfile), [Docker Engine для Ubuntu](https://docs.docker.com/engine/install/ubuntu/)
- **Панель и API.** Play2Go документирует root-доступ к Linux VDS и смену пароля через панель. Возможности Reseller API для обычного VPS остаются неподтверждёнными. Кабинет H1Cloud показывает выбор Ubuntu 24.04 и имеет отдельную документацию API. Применимость конкретных операций API к VPS Standard требует сверки. [База знаний Play2Go](https://play2go.wiki/vds/faq), [статус Play2Go](https://status.play2go.cloud/), [API H1Cloud](https://my.h1cloud.net/api-docs)
- **Будущий CD.** После ручной проверки стенда CI собирает версионированный образ, а защищённое окружение GitHub Actions выкладывает его на ВМ по SSH. После выкладки проверяем `/healthz` и готовность модели, сохраняем предыдущие версии образа и модели для отката. API провайдера нужен для автоматизации управления ВМ. Обновление приложения выполняется по SSH. [План развёртывания](deployment.md)
