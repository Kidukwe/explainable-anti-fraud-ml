Логины и роли подтверждены пользователем 20 октября 2026. Наличие принятого GitHub
доступа проверяется отдельно: таблица ролей не является подтверждением принятия приглашения.
Один owner на задачу, reviewer независим от автора. Актуальные назначения/спринт ведёт
организатор. `docs/backlog.md` — исходный ориентир bootstrap, не актуальный Kanban.

Git-процесс: только постоянная `main`, короткие ветки задач, PR в `main`, squash merge.
Не создавать develop и постоянные ветки направлений. Релизы — теги.

Labels направлений: ml, mlops, backend, frontend, research, documentation.
Типы: feature, bug, experiment, refactor, infrastructure.
Дополнительные: learning-critical, blocked. Приоритет P0/P1/P2 хранить в описании,
чтобы не плодить labels. Обычно один тип + одно направление.

Milestones: M0 Контракт и окружение → M1 Данные/EDA/baseline → M2 Сравнение/XAI →
M3 API/dashboard → M4 VPS/демо. Сроки и имена согласовать командой.
Не создавать все сущности автоматически: стартовый список в backlog.md.

Definition of Done:
- acceptance criteria Issue выполнены и проверяемы;
- один согласованный owner, независимое review, CI прошёл;
- код/контракты/инструкции совпадают, секретов/данных в Git нет;
- для ML есть версия данных, split, seed, зависимости, leakage review, сравнение
  с baseline и воспроизводимые метрики с зафиксированным порогом;
- ограничения и отрицательные результаты отражены;
- автор способен объяснить ключевые решения и AI-assisted код.

Целевая защита main: PR, минимум одно независимое одобрение, фактически существующий
CI check и запрет force push/удаления. Включается после bootstrap и первого рабочего CI,
если разрешает план GitHub. До подтверждённого применения не считать защиту включённой.
Не добавлять несуществующие required checks и не обходить ограничения сменой публичности.
CODEOWNERS.example — неактивный образец; активировать после принятия нужными людьми write-доступа.
Создание Issues/labels/milestones и изменения доступа — только в явно разрешённом объёме.
