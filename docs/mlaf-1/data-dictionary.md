Часть целых значений исходного старого pickle хранится в object-блоках.
В этом дне пропусков нет; полный набор ещё не профилирован.

| Поле | Тип / единицы | Смысл | Доступность / решение |
|---|---|---|---|
| TRANSACTION_ID | int64, ID | Операция | При score; дедупликация/tie, не признак классификатора |
| TX_DATETIME | datetime64[ns], без указанной TZ | Время операции | При score; split и временные признаки |
| CUSTOMER_ID | int64, ID | Синтетический клиент | При score; ключ истории, не числовая величина для baseline |
| TERMINAL_ID | int64, ID | Платёжный терминал | При score; ключ истории, не ПВЗ |
| TX_AMOUNT | float64, условные денежные единицы | Сумма | При score; допустимый признак, реальную валюту не приписываем |
| TX_TIME_SECONDS | int64, секунды | Смещение от начала симуляции | Для хронологии; исключён из входных признаков модели |
| TX_TIME_DAYS | int64, дни | Индекс дня | Для split/бюджета; исключён из входных признаков модели |
| TX_FRAUD | int64, 0/1 | Target генератора | Текущая метка — только target; прошлые созревшие метки доступны для оговорённого агрегата терминала с задержкой 7 суток |
| TX_FRAUD_SCENARIO | int64, 0/1/2/3 | Сценарий генерации | Только offline-диагностика; запрещён во входах детектора/LLM/агрегатах |

Фактического времени подтверждения меток нет. event_time + 7 дней — допущение исследования,
не исходный наблюдаемый столбец. TX_FRAUD=0 означает обычную операцию по генератору.
Известный сценарий не является эталоном объяснения обученной модели.

## Контракт будущих признаков, ещё не реализован

Предлагаются сумма, час/день недели и минимум истории: число операций клиента за
прошлые 24 часа, средняя сумма за прошлые 7 дней, число операций терминала за 24 часа.
Reviewer может сократить набор. Окна включают строго event_time < current_time;
одновременные события исключаются без дополнительного доказательства доступности.
Окна событий не используют метки. Исключение — отдельный признак: число fraud
по созревшим меткам операций того же терминала за окно [current_time − 30 суток,
current_time). Метка исторической операции доступна, если event_time + 7 суток
≤ current_time; незрелые метки не подменяются нулями. Ноль в этом счётчике означает
отсутствие fraud среди доступных меток, а не отсутствие fraud среди всех операций.
При пустой истории счётчик 0, среднее missing;
обработка missing обучается на train. Агрегаты по полному датасету запрещены.

В MLAF-4 проверить все дни на типы/пропуски/дубли/диапазоны/хронологию.
Текущая проверка одного дня не заменяет полноценный EDA или FE.

## Walkthrough для независимого review

Ранее приведённые две строки raw удалены до разрешения условий использования.
Для walkthrough использовать вручную придуманные примеры, не копируя строки raw:
скрыть метки, назвать доступные входы, объяснить границу истории и назвать время
доступности метки по допущению. Score/SHAP здесь не вычислялись; walkthrough
проверяет контракт полей, а не демонстрирует качество модели.
