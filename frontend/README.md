# Frontend — учебный anti-fraud UI

React + Vite, задача MLAF-6. Этот интерфейс не является официальным продуктом OZON.
Реальная модель, inference API, SHAP-артефакты и LLM не подключены.
Demo и production выбираются настройкой запуска, а не пользовательским dropdown.

## Требования и установка

Node.js 22+ и npm. Из корня репозитория, в Git Bash:

```bash
cd frontend
npm ci
```

## Demo без backend

```bash
npm run dev
```

По умолчанию ENVIRONMENT=demo. Адрес обычно http://127.0.0.1:5173/,
точный адрес выводится в терминале. Backend для запуска интерфейса не нужен.
Есть mock-операции, баннер «Демо-режим» и переключатель сценариев.
Все покупатели, суммы, товары и статусы заданы для демонстрации.
Время работы модели не измерялось; 350 мс — искусственная задержка mock-запроса.

## Production без backend

Остановить текущий Vite через Ctrl+C. Запустить:

```bash
ENVIRONMENT=production npm run dev
```

Открыть страницу или обновить её. Видны Production и недоступность API операций;
mock-операций и переключателя сценариев нет. Надпись Production обозначает
окружение, а не готовность модели. API проверки моделью явно остаётся неподключённым.

Для проверки отсутствия fallback при ошибке API:

```bash
ENVIRONMENT=production OPERATIONS_API_URL=/api/not-configured npm run dev
```

Без API на localhost:8000 отобразится ошибка очереди и «Повторить», без mock-подстановки.
Работу с реальным сервисом этот шаг не подтверждает.

Неизвестное окружение вызывает явную ошибку запуска:

```bash
ENVIRONMENT=staging npm run dev
```

Пустое значение ENVIRONMENT тоже является ошибкой. Для возвращения в demo:

```bash
ENVIRONMENT=demo npm run dev
```

В PowerShell установка параметра выглядит так:

```powershell
$env:ENVIRONMENT = 'production'
npm run dev
```

После смены параметра нужно перезапустить Vite и обновить страницу.
Файлы .env автоматически не читаются этой реализацией: используется окружение процесса.
Vite --mode и NODE_ENV не выбирают режим приложения.

## Передача конфигурации через JSON

Единая схема — src/configSchema.js; чтение окружения — config/environment.js.
Frontend загружает GET /config.json со своего origin с cache: no-store:

```json
{
  "environment": "demo",
  "operationsApiUrl": null
}
```

Vite dev/preview отдаёт JSON средствами frontend, с Cache-Control: no-store.
При build плагин записывает config.json в dist. Отдельного backend endpoint
/api/v1/config не требуется. Ошибка JSON/HTTP/значения окружения не включает demo.
Параметры выбираются при запуске/сборке/развёртывании. Dropdown меняет только
сценарий внутри demo и не меняет окружение приложения.
OPERATIONS_API_URL публичен: нельзя помещать пароли/токены в URL.
Поддерживаются публичный HTTP(S)-адрес или путь от корня, например /api/operations.
Адрес, CORS, авторизацию и формат ответа реального сервиса нужно согласовать.

## Сборка и развёртывание

```bash
npm run build
npm run preview
```

Demo выбран по умолчанию. Для production-сборки:

```bash
ENVIRONMENT=production npm run build
ENVIRONMENT=production npm run preview
```

Preview обычно доступен на http://127.0.0.1:4173/. Это локальная проверка,
а не развёртывание рабочего сервиса. Vite preview использует окружение своего
запуска и может проверять другой режим без пересборки JS.

На обычном статическом хостинге используется именно dist/config.json.
ENVIRONMENT, установленный уже после сборки на произвольном сервере, сам по себе
не изменит этот файл. Нужно собрать с нужным ENVIRONMENT либо настроить генерацию
этого JSON при развёртывании и Cache-Control: no-store для него.
Запрещено подменять ошибки API demo-источником в production.

FastAPI/backend, Dockerfile и Compose этой доработкой не изменяются.
Раздачу dist штатным сервисом и передачу ENVIRONMENT в контейнер согласовать
при интеграции. Сам по себе production не означает, что реальная интеграция готова.

## Проверки

```bash
npm test
npm run build
```

npm test запускает Vitest и реальный smoke Vite dev/build/preview для обоих
окружений без backend. Smoke обращается только к localhost; зависимости должны
быть предварительно установлены. Порты выбираются автоматически.

```bash
npm run test:ui
npm run test:ui:watch
npm run test:modes
```

test:ui запускает только Vitest, test:modes — Vite smoke. Smoke-сборки пишутся
в node_modules/.cache/mode-check и не коммитятся. Обычная сборка — frontend/dist.
Существующий CI job с npm ci / npm test / npm run build автоматически включает
новые проверки. Успех удалённого CI нужно подтвердить после push.

## Проверка интерфейса

1. Запустить demo. Проверить баннер, три операции и вкладки из tab.json.
2. Нажать № 10001: открывается карточка, заказ 1431, покупатель Иванов, инициалы ИИ.
3. Сменить сценарий: карточка остаётся открытой, старый ответ сразу очищается.
4. Пройти семь состояний ниже. Пустая очередь закрывает карточку и обнуляет счётчики.
5. Проверить поиск/фильтр/вкладки, пустой поиск, открытие и закрытие заказа/товара.
6. Проверить CSV. Файл mock-transactions.csv содержит демонстрационную выборку.
7. Переключиться с готового результата на другую операцию: старый ответ не виден.
8. Проверить клавиатуру, длинные подписи и ширины 390/1280 px.
9. Запустить production без API и с недоступным API: demo-инструментов и fallback нет.

| Сценарий demo | Ожидаемый результат |
| --- | --- |
| Загрузка | Проверяем операцию…; состояние остаётся загрузкой |
| Пустая очередь | В очереди нет операций; карточки нет, счётчики 0 |
| Ошибка сети | Ошибка соединения и Повторить; повтор возвращает ту же mock-ошибку |
| Модель недоступна | Отдельное сообщение о недоступности модели |
| Готовый ответ — mock | Отдельные блоки Score, SHAP, LLM, Checks и демонстрационный текст |
| Объяснение отсутствует | Текстовое объяснение отсутствует |
| Отказ проверки — mock | Отказ ответа с причиной, без обвинения покупателя |

Все mock-сценарии пока имеют score=null и shap=null: они не подтверждают
отображение реальных SHAP-артефактов или числового score. Score не называется
вероятностью без определения шкалы. SHAP не доказывает факт фрода.
Статусы Approved/Banned/Consideration — заданные demo-значения.
Иллюстрация аэрогриля используется только для аэрогриля; прочие товары имеют заглушку.

Vitest проверяет гонки ответов, чужой operationId, старый сценарий, повтор запроса,
отсутствие mock-fallback и очистку устаревших данных. Эти проверки дополняют,
но не заменяют визуальную приёмку и независимое review.

## Структура

- src/main.jsx — точка входа RuntimeApp.
- src/RuntimeApp.jsx — чтение конфигурации и выбор demo/production.
- src/configSchema.js, config/environment.js — единая публичная конфигурация.
- src/DemoApp.jsx — очередь, карточка, вкладки и demo-сценарии.
- src/ProductionApp.jsx — настроенный API очереди или недоступность, без mock-источника.
- src/runtimeConfig.js — запрос конфигурации и временный адаптер очереди.
- src/OperationCheck.jsx — demo-проверка с защитой от старых ответов.
- src/tab.json — вкладки с уникальными id, title, content; content — ключ реестра.
- docs/contract-mapping.md — текущие поля и несогласованные границы API.
- docs/review-checklist.md — инструкция и незаполненный протокол Алины.
