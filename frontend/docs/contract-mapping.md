# Границы frontend и сверка контракта

Статус: интеграция с реальным inference API не выполнена.
Основание: `../docs/contracts.md` в репозитории — перечень требований к будущему
контракту. Согласованная версия схемы предсказания пока не предоставлена.
При приёмке указать ссылку на конкретный draft и commit SHA.

## Конфигурация приложения

Frontend читает `GET /config.json` со своего origin. В Vite dev/preview JSON
отдаёт frontend-плагин, при build он создаётся в dist. Backend не изменяется.
Поля: `environment: demo|production`, `operationsApiUrl: string|null`.
Секреты, пароли и токены в конфигурацию не входят. Это предлагаемая схема
конфигурации frontend, а не уже принятый командой API-контракт.

## Сопоставление имеющихся mock-полей

| Поле draft-контракта | Внутреннее поле UI/mock | Место в UI | Состояние сверки |
| --- | --- | --- | --- |
| Не согласовано | transaction.id / operationId | Номер операции, привязка ответа | Требует согласования |
| Не согласовано | transaction.orderId | Заказ | Требует согласования |
| Не согласовано | transaction.amount | Сумма; сейчас UI использует рубли | Валюту и единицы согласовать |
| Не согласовано | transaction.status | Approved / Banned / Consideration | Это demo-статус, не вывод модели |
| score: упомянут в требованиях | result.score | Score модели | Шкала и диапазон не определены; mock null |
| Explainability schema не определена | result.shap | SHAP — вклады признаков | Формат/единицы согласовать; mock null |
| Не согласовано | result.explanation | LLM — текстовое объяснение | Demo-текст, не ответ подключённой LLM |
| Не согласовано | result.checks.status / reason | Checks | Внутренние demo-статусы notRun/rejected |
| Ошибки 422/503 упомянуты в требованиях | error.code / message / canRetry | Сообщение об ошибке, повтор | Формат тела ошибки не согласован |
| threshold | Нет | Нет | Не добавлять произвольно |
| model_version | Нет | Нет | Не добавлять произвольно |
| feature_schema_version | Нет | Нет | Не добавлять произвольно |
| request_id | Нет | Нет | Не добавлять произвольно |

Временный адаптер очереди в `runtimeConfig.js` ожидает объект `operations`
с массивом записей `id`, `orderId` (строки), `amount` (конечное число),
`status` (approved/banned/consideration). Это не утверждённая схема API.
После получения draft адаптер и тесты нужно привести к нему.

## Передать владельцу backend / интеграции

1. Согласовать поля JSON и способ предоставления `/config.json` в общем сервисе.
2. Согласовать API очереди, валюту, ID, статусы, ошибки, CORS и авторизацию.
3. Согласовать API проверки/объяснения и источник доступности модели.
4. Подключить frontend к штатному сервису и настроить ENVIRONMENT в Docker/Compose.
5. Подтвердить актуальную версию draft и результат сверки с Алиной.

SHAP объясняет выход модели и не доказывает причинность или факт фрода.
Score не называется вероятностью без определения шкалы в контракте.
