# Инструкции для Codex

Учебный командный проект. Партнёр задания — OZON; не объявлять официальным продуктом.
Модульный монолит: ML в src/antifraud, HTTP в backend, UI в backend/static.
HTTP/ML не должны импортировать учебный workspace. Node не нужен для этого сервиса.
Не добавлять БД, микросервисы, MLflow или оркестрацию без доказанной потребности и ADR.

ROUTINE: конфиги, инфраструктура, документация, CI — реализовывать самостоятельно.
LEARNING-CRITICAL: EDA, генератор учебных данных, preprocessing, FE, baseline,
моделирование, evaluation, отбор признаков, error analysis, XAI — по умолчанию
дать краткое объяснение, план, минимальную подсказку и ревью попытки пользователя.
Не писать полное решение до явного разрешения; разрешение пользователя отменяет
этот default. Не превращать обучение в запрет на работу. Не запускать большой курс.
Личные учебные базы, переписка и материалы не входят в этот репозиторий.

До правки читать относящийся код/Issue, сохранять изменения пользователя. Малые PR,
явные контракты, типы на границах; без фиктивных метрик и неподтверждённых claims.
Сначала определить split и доступность признаков на момент предсказания. Fit всех
преобразований только на train. Test не использовать для порога/подбора параметров.
SHAP объясняет модель, не причинность и не факт фрода; LLM необязательна и не истина.

Проверки: uv run ruff check ., uv run ruff format --check ., uv run pytest.
Новые тесты — на поведение/ошибки/контракты, не зеркальные implementation-тесты.
Docker проверять при изменении контейнера. Не заявлять непроведённые проверки.
Не коммитить data/artifacts/secrets/venv. Remote repo, Issues, участники,
VPS и публикация требуют явного разрешения. Не менять глобальный Codex config.


Командный remote: https://github.com/Kidukwe/explainable-anti-fraud-ml.git.
Постоянная ветка только main; короткая feature/<реальный-ID>-<topic> → PR в main.
Релизы — теги; develop/постоянные ветки направлений и пустые ветки заранее не создавать.
Не управлять Kanban и учебным планом. Зависимости и глобальные конфиги без явного
разрешения не менять. После задачи: изменённые файлы, проверки, риски, безопасный шаг.
